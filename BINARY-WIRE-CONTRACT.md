# V13.1 binary wire contract

Source admission, canonical values, binary representation and hook adaptation are separate stages. Neither codec changes source admission or the fixed product evaluator. Both candidates encode the same row-oriented dynamic object/list tree and existing envelope fields. Protobuf uses the generic schema in experiments/v131/wire.proto; MessagePack uses native maps/arrays/scalars with exact-integer extension 42. No columnar representation, topic-specific code generation, JSON text/blob conversion or decimal-text numeric wire is permitted. This generic wire capability does not add evaluator topics or query grammar.

## Values and source semantics

| Layer/value | Contract |
|---|---|
| ProductRow | id/category UTF-8 strings; omitted label defaults to Missing; unknown admitted struct fields ignored. Results contain only typed product fields. |
| Label | Missing, Null, Value("") and Value(nonempty) remain distinct; source JSON null is not the tagged Null variant. |
| Source integer | Native num-bigint 0.4.8 grammar `[+-]?[0-9][0-9_]*`, total input and canonical output <=10001 ASCII bytes; canonical plus/separators/leading zeros removed, negative zero becomes zero. |
| Canonical exact integer | Sign octet 0 or 1, then minimal big-endian unsigned magnitude; zero is sign 0 and empty magnitude. No leading zero magnitude or negative zero. Maximum positive 10001 decimal digits, negative 10000 digits. Bytes checked before construction and exact decimal capacity checked after bounded BigInt construction. |
| Decimal | Existing coefficient/scale object. Coefficient uses the exact binary integer variant, never Number/f64/text. Scale is checked signed safe metadata in [-10000,10000]. Canonical zero scale is 0; trailing decimal zeros removed while scale > -10000. Source coefficient construction differs from human decimal-literal parsing, whose coefficient bound is 10000 digits. |
| Metadata | Existing safe integers retain Number after explicit [-9007199254740991,9007199254740991] checks. Connection/source-sequence decimal-string API fields are encoded as exact unsigned values and adapted back to strings; u64 bounds are checked for these fields. |
| Actual strings/bytes | UTF-8 scalar strings and native binary bytes, including empty values. Unpaired JS surrogates rejected. Binary synthetic fixtures exercise wire flexibility only. |
| Hook API | Exact quantity/coefficient remain canonical strings, amount remains coefficient/scale; BigInt conversion is measured as adaptation. No public type/inference migration. |

Signed i64 [-2^63,2^63-1], unsigned u64 [0,2^64-1], 2^53 neighbors and the wider domain all use the same exact variant and hook types independent of magnitude. Zero/false/empty values are retained; an absent map key differs from a key with null. Both candidates carry identical semantic values.

## Protocol and bounded admission

The experimental peers use the existing single loopback WebSocket and authentication/Origin policy, with an explicit v13 codec-specific subprotocol and protocol version 13. A build contains one codec; no runtime registry or JSON downgrade. Only hello/ping/command/command_rejected enter the server; ready/pong/result/ack/request_error exit. Authentication token, nonce, incarnation, connection, IDs, acquisition, source cut and query metadata retain the existing lifecycle checks after complete decode. Invalid frames terminate the peer before command admission. Output encode failure closes the consumer; a durable source commit is not rolled back and pending completion remains uncertain.

Source request envelopes retain the existing 65536-byte JSON admission bound. Binary request and publication frames <=4194304 bytes; unchanged output queue <=8388608 bytes and per-client+16 frames, based on actual encoded bytes. Common parser limits: semantic depth 128 (root at zero), total values/fields 65536, collection length 8192, UTF-8/string/binary length <=frame budget. Exact magnitude <=4154 bytes before allocation/conversion; canonical decimal capacities remain the authoritative tighter check. Boundary and boundary+1 must be exercised.

Before library decode, bounded structural preflight checks every declared length against remaining bytes and limits, and rejects invalid UTF-8, nonminimal/overlong encodings, conflicting/duplicate Protobuf variants, invalid extension IDs, unsupported float markers and trailing bytes. Semantic validation after the bounded decode rejects duplicate object keys, wrong scalar types and invalid exact values before publication or command admission. Protobuf unknown field numbers and MessagePack unknown extension IDs are rejected in version 13. Additive object fields are wire-admissible; existing typed source/query admission still governs their semantic use. Incompatible protocol versions fail explicitly. A later permissive evolution policy requires a new negotiated version; source ignored-field behavior is not automatic protocol evolution.

The publication oracle explicitly supports true and category-equality predicates, both sort directions and safe windows, plus the existing open/change-query/change-window/close/source-cut operation schedules. Unsupported predicates must fail explicitly; other native predicate behavior remains covered by preserved native/golden/reference/direct-WASM tests. Expected row canonicalization and poison cases are fixed independently of evaluator output.

Library depth mapping: common preflight accepts semantic depth128 and rejects depth129 before library decoding. rmpv receives 2×128+4 internal levels; protobufjs uses 3×128+4 wrapper levels; the isolated vendored `view-wire-prost` package disables its wrapper guard behind the finite preflight; registry `prost` used for source ingestion retains its default guard. The unchanged source parser admits 122 NOTs in the full request envelope and rejects 123. See QUERY-ADMISSION-AND-ERROR-CONTRACT.md for source admission and sequenced recoverable errors.

Request query `limit` is u64, not universally safe Number metadata. The JSON baseline admits large requested query limits when the actual result fits. This value uses the same unsigned exact magnitude representation as connection/source_sequence; the local JS admission ABI retains a canonical string and the native adapter restores u64. Row/index/total/result metadata retains its existing safe-integer bound. Neither codec parses product source spelling.

Preparation cost includes conversion from the native in-memory result tree. Protobuf uses its generated message tree; MessagePack uses the pinned rmpv value API, including its tree conversion. These costs are measured, with preparation plus encoding used for the decision. The comparison is of these concrete library integrations, not a claim about every possible implementation of either format.

The unchanged JSON source decoder admits 100 nested unknown groups and rejects 101; the defective Protobuf candidate admitted 101 and 120. Those red logs and the disqualified measurement attempt are preserved. The final candidate gate tests depths 0, 99, 100, 101, and 120 in every peer and checks distinct Cargo package identities/features.
