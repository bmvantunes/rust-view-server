# V13 predeclared codec decision rule

Recorded before candidate measurements. Correctness, full exact-domain parity and bounded hostile decoding are mandatory; a failing candidate cannot win. Compression is off for all paths. Both use the same row-oriented tree, field names, source contents, seeds, windows, subscription counts and adaptation semantics. Compare immutable JSON separately; it is not a production fallback.

Use at least five independent process runs per candidate/workload, alternate PB/MP order (and rotate JSON), discard a declared warmup, retain every subsequent sample. Workloads: 96 rows/70+1 narrow subscriptions; 512 rows/16+1 subscriptions with 32-row windows; integer-, decimal-, string- and mixed-heavy product distributions. Native-binary synthetic byte fixtures are separately labeled. Cold, live, navigation, burst and sparse phases must be identified.

For principal actual-pipeline metrics (server encoding CPU/time, Worker decode+adaptation, same-clock request receipt p95, hook observation p95, encoded bytes), compare paired per-process summaries. Practical equivalence means ratios are within 0.90..1.10 for time metrics (or absolute difference <=100 microseconds for encode/decode and <=1 ms for end-to-end p95) and within 10% for bytes across representative workloads, with no consistently adverse tail/queue/resource behavior. Report p50/p95/p99/max and variability; sample counts do not substitute for independent process repetitions.

A Protobuf win requires a repeatable advantage beyond equivalence on a workload-relevant principal metric in at least four of five paired runs, with no material countervailing regression in another principal metric; byte savings must exceed 15% to be material on their own. A MessagePack win requires practical equivalence or a similarly repeatable overall advantage with no material countervailing regression. Practical equivalence favors MessagePack for runtime flexibility and lower ceremony. Conflicting CPU/latency/byte tradeoffs, unstable run-to-run results or incomplete essential measurements mean inconclusive; do not force a production switch. No C++ inference or capacity extrapolation.

Separate raw timings: Rust canonical-value preparation and codec encoding; Worker structural preflight/library decoding and exact-value adaptation; main-thread receipt and hook observation; observable structured-clone interval (same browser time origin verified), request settlement; actual queue bytes; server ps CPU/RSS and available browser performance/heap metrics. Unavailable allocation/CPU/heap quantities are explicitly unavailable. Never subtract unrelated clocks or call receipt paint latency.

Pilot qualification note (before repeated comparison): four back-to-back source records at 70 subscriptions exceeded the preserved 86-frame queue and correctly terminated that consumer. Keep this as bounded-pressure evidence, not latency data. Measured bursts therefore use one mounted hook plus one peer, four records per burst; cold/live/sparse retain 70+1 or 16+1. All candidates use this same phase transition. No queue budget is increased. Warmup and pilot repeats (negative indices) are excluded from selection.

Timing units for the decision: per-frame server preparation plus encoding p95 uses the 100 microsecond absolute tolerance. Preserve encoding-only and preparation-only distributions separately. Warmup updates are correctness-checked but excluded from steady-state timing distributions; cold readiness is reported separately. Total bytes include the complete, identical protocol schedule. Transfer observation uses absolute browser time origins and reports the residual arrival interval separately from the synchronous postMessage call; it is not an isolated copy-engine measurement. All codec qualifications must pass before collection.

Final instrumentation pilot: Chromium performance clocks are quantized at roughly 100 microseconds; aligning Worker/main time origins can yield a residual near -100 microseconds. Preserve signed intervals with a conservative ±200 microsecond uncertainty. Do not use this cross-context residual as a principal decision metric; same-main-clock request and hook intervals remain principal.
