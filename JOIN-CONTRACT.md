# Bounded joins v1

`defineJoin(catalog, {left:{topic,as}, right:{topic,as}, kind:'inner'|'left', cardinality:'many_to_one', on:{left,right}, limits:{maxLeftRowsPerKey,maxOutputRows}})` returns an immutable typed handle accepted by existing whole-result and viewport hooks. Select, filter, sort, group and aggregate fields are qualified `alias.source.path`. Existing text predicates, global aggregates and HAVING compose in that order after the join. Dynamic LEFT/INNER kinds preserve possible right-root nullability.

Exactly two distinct configured topics and one equality pair are supported. Key kinds and enum domains must match; null/missing never match. Right non-null keys must be unique across the entire retained relation. LEFT emits a null right alias when unmatched and preserves source nested presence when matched. Self joins, chains, composite equality and other cardinalities fail admission. `bounded_joins_v1` negotiation is required in addition to capabilities for selected language features.

Join relations share existing engine evaluators and own bounded key indexes. Left fanout <=1024; output <=min(100000, configured left retained-row ceiling), checked before WHERE/filtering; <=32 distinct join definitions; pending affected contribution IDs <=65536. Right changes touch only old/new-key left matches. Later uniqueness/fanout/output violations fail dependent queries without rolling back canonical commits or failing unrelated queries. Last subscription close releases relation indexes. Existing selected output/window limits remain.

`jid1:` + SHA256 of JSON `[1,leftTopic,leftFingerprint,rightTopic,rightFingerprint,leftAlias,rightAlias,leftKey,rightKey,kind,'many_to_one',leftRowId]` is stable across right match/unmatch and reconstruction. Join result kinds are `join_v1`, `join_grouped_v1`, `join_global_v1`; descriptors bind the canonical join signature, inner aggregate shape and qualified projection. Group/global identities use the deterministically derived internal relation identity. Exact cross-language vectors are exercised by `scripts/test-join-contract.ts`.

Both dependencies undergo existing fresh authority guards at acquisition/publication; both must be bootstrapped and retention-safe. Close retains authority checking but remains possible while retention is pending. Publications carry `source_cuts:{topic:{schema,source_sequence,content_version,next:{partition:nextOffset}}}` for exactly both sources. These are independently committed/derived cuts, not a cross-source atomic transaction or an additional browser monotonic-clock guarantee. The changed source is acknowledged using the existing protocol; timer expiry changes content without advancing NEXT. Existing acquisition/shape/incarnation checks protect result bases.

Qualification sources: `native/tests/joins.rs`, `browser/src/join-contract.test-d.ts`, `scripts/test-join-contract.ts`, `scripts/run-join-kafka.py` and `scripts/test-join-kafka.mjs`. The mounted harness uses `window.joinDemo.start(url,token,catalog,fieldPatches=false)`, `observe()`, `dispose()`. Optional fieldPatches is for the lead's combined F5 gate; this F3 candidate itself is based on the pre-F5 delta implementation.

Author status and exact source/binary/evidence bindings are in the sibling `joins/evidence/HANDOFF.md` and `CANDIDATE.json`; only a separate reviewer may declare acceptance. Expanded-schema combined limits (64 fields/parents and path depth) remain applicable; overly wide joins are explicitly rejected. No production, scheduler, operations, gRPC or replacement-engine qualification is claimed.
